# План розробки додатку для боротьби з прокрастинацією: "FocusFlow"

## 1. Контекст для AI (System Context)
Цей документ є архітектурним планом та інструкцією для розробки додатку "FocusFlow". 
**Роль AI:** Ти — Senior Full-Stack розробник. Твоє завдання — покроково реалізовувати описаний нижче функціонал, писати чистий, модульний та добре задокументований код, дотримуючись сучасних стандартів.

## 2. Опис проєкту
"FocusFlow" — це додаток, розроблений для допомоги користувачам у боротьбі з прокрастинацією та відволіканням. Він поєднує в собі техніку Pomodoro, управління завданнями та механізми блокування відволікаючих факторів.

### Основні функції (MVP):
1. **Task Manager:** Створення, редагування, видалення та пріоритезація завдань.
2. **Pomodoro Timer:** Налаштовуваний таймер для фокусування (робота/коротка перерва/довга перерва).
3. **Strict Mode (Блокувальник):** Блокування певних вебсайтів або додатків під час сесії фокусування.
4. **Статистика:** Відстеження часу, витраченого на продуктивність (денна/тижнева статистика).

## 3. Технологічний стек (Tech Stack)
*   **Frontend:** React (з TypeScript) або Next.js.
*   **Стилізація:** Tailwind CSS, Framer Motion (для анімацій).
*   **State Management:** Zustand або Redux Toolkit.
*   **Локальне збереження:** LocalStorage або IndexedDB (через Dexie.js).
*   **Блокувальник (залежить від платформи):** 
    *   Якщо це Web/Extension: Chrome Extensions API (`chrome.webRequest` або `chrome.declarativeNetRequest`).
    *   Якщо це Desktop (Tauri/Electron): Взаємодія з системним файлом `hosts`.

## 4. Архітектура та структура папок
Створюй компоненти та логіку відповідно до цієї структури:
```text
src/
 ├── components/       # Перевикористовувані UI компоненти (Buttons, Modals)
 │    ├── timer/       # Компоненти таймера
 │    ├── tasks/       # Компоненти списку завдань
 │    └── layout/      # Навігація, хедер, футер
 ├── store/            # Zustand stores (useTaskStore, useTimerStore)
 ├── hooks/            # Кастомні хуки (usePomodoro, useBlocker)
 ├── utils/            # Допоміжні функції (форматування часу, валідація)
 ├── types/            # TypeScript інтерфейси
 └── App.tsx           # Головний компонент
```

## 5. Покроковий план реалізації (Для AI)

*Інструкція для AI: Не пиши весь код відразу. Чекай від користувача команди "Виконай Крок X", перш ніж генерувати код для відповідного етапу.*

### Крок 1: Ініціалізація проєкту та базовий UI
1. Створити базовий макет (Layout) з використанням Tailwind CSS.
2. Додати навігаційне меню (Dashboard, Timer, Settings).
3. Налаштувати глобальну тему (світла/темна).

### Крок 2: Менеджер завдань (Task Store & UI)
1. Створити `useTaskStore` (Zustand) з масивом завдань (id, title, status, estimatedPomodoros).
2. Реалізувати CRUD-операції для завдань.
3. Створити компонент `TaskList` з можливістю відзначати завдання як виконані.
4. Налаштувати збереження завдань у LocalStorage.

### Крок 3: Модуль Pomodoro Таймера
1. Створити `useTimerStore` (Zustand) для керування станом таймера (work, shortBreak, longBreak).
2. Написати кастомний хук `useTimer`, який обробляє логіку зворотного відліку (`setInterval`), паузи та скидання.
3. Створити круговий індикатор прогресу таймера (SVG + Tailwind).
4. Інтегрувати вибір поточного завдання зі списку завдань до таймера.

### Крок 4: Механізм фокусування та блокування (Strict Mode)
1. Створити логіку "Focus Mode", яка забороняє переривати таймер (або штрафує за це).
2. Створити список "Чорний список" (Blacklist) для URL-адрес.
3. (Залежно від середовища) Згенерувати скрипт для блокування доступу до сайтів з чорного списку, коли таймер активний.

### Крок 5: Статистика та Гейміфікація
1. Записувати кожну успішну сесію Pomodoro в базу даних.
2. Створити компонент `StatsDashboard` для відображення графіка продуктивності (наприклад, за допомогою `recharts` або `chart.js`).
3. Додати систему щоденних "стриків" (Streaks) для мотивації користувача.

## 6. Правила написання коду для AI
1. **Типізація:** Завжди використовуй строгу типізацію TypeScript. Описуй `interface` для всіх сутностей.
2. **Модульність:** Розбивай великі компоненти на дрібніші (Single Responsibility Principle).
3. **Коментарі:** Додавай короткі JSDoc коментарі для складних функцій і хуків.
4. **Обробка помилок:** Завжди враховуй крайні випадки (empty states, invalid inputs).
5. **Чистота:** Не залишай `console.log` у фінальному коді.
